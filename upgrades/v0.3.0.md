# v0.3.0

相对 `v0.2.0`：插件可以在工作台设置页声明并保存配置，拉起子进程时注入为本插件的环境变量。

## 变更

### 新增

- 侧栏底部「设置」进入设置页。声明了 `configSchema` 或 `settingsEntry` 的插件会出现在导航里，可搜索，返回时回到进入前的页面
- 宿主按声明生成字符串、开关、数字、下拉和目录表单。整节校验通过后写入用户数据目录的 `plugin-settings.json`，按插件 id 分块
- 密钥以密码框显示，不回显已保存明文。留空保存保留原值，「清除」后该键为空字符串
- 每个字段可「恢复默认」，只改草稿，仍需点「保存」才写入
- 插件后端可通过 `ctx.getPluginConfig()` 与 `ctx.pluginEnv()` 读取本插件配置。拉起子进程时传入 `{ env: ctx.pluginEnv() }`，不改宿主自己的环境变量
- 插件可提供 `settingsEntry` 自带设置页，与生成的表单读写同一块配置，且不能读取其他插件
- 覆盖安装保留配置。卸载已安装插件且目录删除成功后，删除对应配置块。配置文件损坏时按空配置启动
- 插件开发说明写明配置接法。工作台不读写 `.env`；单独运行时可自行加载 `.env`，已有环境变量优先。打包时排除 `.env`

## 升级注意

- 桌面安装包在 GitHub Release 页，由 Actions 在 tag 推送后上传
- 不要删除 Release 上的 `latest*.yml` 与 blockmap，否则已安装客户端无法更新
- 核对 `package.json` 的 `version` 为 `0.3.0`（不含 v）
- 已有插件不改 manifest 也能继续用。要使用设置页，需在自己的仓库里声明 `configSchema`，并在拉起脚本时传入 `ctx.pluginEnv()`
