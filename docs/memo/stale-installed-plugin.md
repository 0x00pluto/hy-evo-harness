# 换清单 id 后本机旧安装卸不掉

插件安装目录按清单 id 命名。id 一换，旧目录还在用户数据下的 `installed_plugins` 里，新安装不会覆盖它。加载失败时列表里往往没有这一条，也就没有卸载。

**这不是已排期的功能。** 不占 PRD 序号。以后若做，另开 PRD。

---

## 现象

以小红书为例：以前一个清单 id，后来改成另一个（例如带 `app-dexbuddy-` 前缀）。本机同时留下：

- 旧 id 目录（还在磁盘上）
- 新 id 目录（市场或 zip 新装的）

旧的那一份挂着，插件页不好卸，或点卸载对不上目录。

## 原因

- `replaceInstalledPlugin` 只覆盖**同一个** id 的目录。新 id 是另一条路径。
- `scanAndLoadPlugins` 读清单失败时 `tryLoadDirectory` 只打日志，不进插件列表。
- `uninstallInstalledPlugin` 按当前注册表里的 id 拼 `installed_plugins/<id>`。目录名和清单 id 不一致时，会删错地方或删不掉。

点开头的覆盖备份（`.{id}.bak`）本来就不是插件，不要当成这一条。

## 以后要的结果

人能在插件页看到 `installed_plugins` 里每个非备份子目录，并卸载**扫描到的那个目录**（以及该 id 已有的本机设置）。新安装留下。不自动迁移、不静默删旧 id、不改云端已购记录。

## 不做

- 积分页「已购插件」里的旧 id
- 给全部用户机器做批量清理
- 改市场商品 id 的发布流程
