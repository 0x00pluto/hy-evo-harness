# 插件打包签名（已讨论，不立项）

签名挡的是「仍声称自己是已上架 id A」；挡不住「改成货架上没有的 id，走未上架放行」。本轮不写 PRD、不改代码。

00016 孤儿规则维持现状，不拆 `installed_plugins`。

---

## 起因

有人把包 B 改成包 A 的清单 id，想花 A 的买断。权益看的是 `plugin.manifest.json` 自报的 id（宿主盖 `X-Plugin-Id`），不是安装目录从哪来。市场 / zip 分目录挡不住这条，否决。

曾想对标 Chrome：作者自己签名、不可逆、签名缺失或内容被改就不能当这个已买插件跑。讨论停在这里，没有开工。

## 签名能挡什么

对标 Chrome 扩展 / minisign，不造轮子、不加密源码。

- 作者一把私钥只生成一次，放本机（例如 `~/.minisign/`），不要进 git、不要进 zip。丢了就不能再发同一 id 的更新（货架改钉新钥等于换作者身份）。
- 发版时按 pack 规则列出文件，写成 `SHA256SUMS`，再用同一把钥签出 `SHA256SUMS.minisig`。
- 货架 `index.json` 按插件 id 钉死作者公钥。宿主验签只用这把钥，不信包里自带的公钥。
- 当前发布是作者推 tag、本仓 Action 打包。私钥若只在作者电脑，CI 签不了：要么打 tag 前本机签一次把清单提交进即将打 tag 的提交，要么私钥进 GitHub secret（管理员也能签，弱于「钥匙只在作者电脑」）。

声称自己是 A、却删签名再用自己的钥重签：货架上 A 钉的是作者公钥，验失败，不加载，花不了 A 的买断。换钥匙等于换身份，不是还当原来那个插件。

Chrome 把扩展 id 做成公钥哈希，换钥必换 id。我们继续用人读 id（如 `manju-studio`），用货架钉钥达到同一效果。不改成哈希 id，会拆现有安装目录、买断和 `X-Plugin-Id`。

## 真正没堵住的洞

买断闸在 `src/main/host-egress.ts` 的 `assertEntitled`：清单 id 不在商城目录就直接返回（`prd-00015` 拍板的未上架放行）。登录仍要过；烧模型仍报价。省的是插件买断，不是 token。

因此：下载已买断的 A，把 id 改成货架上没有的新 id，不必签名也能加载、也能烧模型。删签名、用自己的钥重签，改变不了这件事——一改 id 就不再声称是 A，验签和 A 的买断都跟它无关。

抄源码发成自己已上架的 B，花的是 B 的买断。签名不防复制。

## 以后若要堵

改的是放行范围，不是先上签名。例如：已安装包（市场 / zip）不走未上架放行；或烧模型必须货架上有这个 id。会伤到未上架自研插件，以及「加载本地目录」（对标 Chrome 未打包扩展，默认仍会放行）。

## 不做

- 本轮无代码、无 PRD
- 不加密源码、不做 `.crx` 容器或平台代签
- 不把清单 id 改成公钥哈希
- 不改 00016 孤儿规则，不拆安装目录
