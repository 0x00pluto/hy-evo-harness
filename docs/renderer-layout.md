# 渲染层布局

工作台壳的设置页和插件页现在共用一份分栏骨架。这篇记下当前做法，以及以后什么情况下再引入 Lit。

## 现在：一份分栏

设置页和插件页都待在 `src/renderer/index.html` 的 `#split-layout` 里。工作区表面把整段隐藏。宽侧栏（字标和应用列表）不是这套分栏，仍用自己的宽度。

骨架上的度量只写在 `.split-*`：左栏标题的字号、字重、行高，搜索框，分区标题，以及内容区 `28px 32px 40px` 的内边距。页面只往自己的列表和主槽填内容，不再各写一套栏的间距。

左栏宽度在画面上是一个变量 `--split-nav-width`。存储仍是两把钥匙，`dex.settingsNavWidth` 和 `dex.pluginsNavWidth`。切到哪个表面，就读哪一把。这样拖设置页的分隔，不会改掉插件页上次的宽度。

渲染层继续是现有的 HTML、CSS 和 JavaScript，没有打包器，也不引入组件库。

## 以后：Lit 具名插槽

具名插槽是 HTML 标准：`<slot name="nav">` 放在阴影树里，页面用 `slot="nav"` 填进去。Chrome、Firefox、Safari 都已支持多年，Electron 44 的 Chromium 可以直接用。Lit 是在这层标准上写组件的薄库，由 Google 维护，现行稳定线是 Lit 3，用在生产环境的组件系统里。样式写在组件内部之后，页面改自己的标题间距时碰不到骨架的内边距。

下面这些做法都不如它适合这个壳以后的那一步：

- 只写原生自定义元素、不用 Lit：插槽是同一套，少一个依赖。触发条件一旦达到，就要手写更新和多份组件，样板比 Lit 多。
- 声明式阴影 DOM：可以让骨架的 HTML 先画出来。它补的是少跑一点 JavaScript 才看得到骨架，不替代插槽，也不解决组件变多之后的更新。以后若上 Lit，可以一起用。
- Alpine：没有插槽，锁不住骨架的盒子。默认构建用表达式求值，和以后若加内容安全策略也不合拍。
- React 或 Vue 的 slot：能力够，但要整页构建和组件运行时。比 Lit 重，也罩不住插件页里的 `webview`。

因此以后的那一步是：一个 Lit 布局组件，用平台具名插槽卡住左栏、分隔和内容区内边距，设置页和插件页只填槽。

触发条件（满足其一再做）：

- 第四个同样的分栏表面出现，而且骨架间距又被改散。
- 单个页面文件里拼 DOM 超过大约 800 行，并且列表渲染散落多处。

在那之前不安装 Lit，也不把 Lit 写进渲染代码。
